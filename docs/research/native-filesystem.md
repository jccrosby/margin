# Filesystem guarantees for native Margin

Margin needs platform-specific checks for two guarantees. Source reads must stay inside the registered root. Private data must stay inaccessible to other ordinary local users. The current macOS checks do not carry over to Linux and Windows as written.

## Source access

- Margin stores canonical root paths. It checks parent directories and regular files before opening sources. Source IDs keep slash-delimited relative paths. This makes native path parsing and filesystem identity part of the port. [Registration checks](https://github.com/jccrosby/margin/blob/882b275ad93ecde9ee2c1fa93d3ac322c533b8d2/src/registry.ts#L142-L163) · [Source checks](https://github.com/jccrosby/margin/blob/882b275ad93ecde9ee2c1fa93d3ac322c533b8d2/src/sources.ts#L36-L113)
- **macOS** uses Darwin's `O_NOFOLLOW_ANY` in the source reader. Darwin checks all path components for symlinks at open time. **Linux** `O_NOFOLLOW` checks the final component only. Linux offers all-component checks through `openat2`, which the Node 26 filesystem API does not expose. The port needs an explicit containment guarantee for Linux when paths can change during access. [Margin source reader](https://github.com/jccrosby/margin/blob/882b275ad93ecde9ee2c1fa93d3ac322c533b8d2/src/read.ts#L3-L21) · [Darwin flag](https://github.com/apple/darwin-xnu/blob/main/bsd/sys/fcntl.h) · [Linux openat2](https://man7.org/linux/man-pages/man2/openat2.2.html) · [Node filesystem API](https://nodejs.org/download/release/v26.3.1/docs/api/fs.html#file-open-constants)
- **Windows** does not expose `O_NOFOLLOW` through Node. NTFS junctions and symlinks can redirect access. Different path spellings may name the same object. Decide which aliases, namespace forms, and reparse points to support. Validate source ID components against native separators before building a filesystem path. [Node open flags](https://nodejs.org/download/release/v26.3.1/docs/api/fs.html#file-open-constants) · [Windows link types](https://learn.microsoft.com/en-us/windows/win32/fileio/hard-links-and-junctions) · [Windows path rules](https://learn.microsoft.com/en-us/windows/win32/fileio/naming-a-file)

## Private storage and recovery

- The registry stages writes in a temporary directory. Saved notes require owner-only directories and files. The index checks the database and sidecars. Evidence extraction stages source bytes in the OS temporary directory. The privacy decision should cover all four paths. [Registry writes](https://github.com/jccrosby/margin/blob/882b275ad93ecde9ee2c1fa93d3ac322c533b8d2/src/registry.ts#L113-L139) · [Saved notes](https://github.com/jccrosby/margin/blob/882b275ad93ecde9ee2c1fa93d3ac322c533b8d2/src/notes.ts#L37-L71) · [Index checks](https://github.com/jccrosby/margin/blob/882b275ad93ecde9ee2c1fa93d3ac322c533b8d2/src/index.ts#L38-L54) · [Evidence snapshots](https://github.com/jccrosby/margin/blob/882b275ad93ecde9ee2c1fa93d3ac322c533b8d2/src/evidence.ts#L58-L71)
- On Linux filesystems with POSIX ACLs, the group mode bits reflect the ACL mask when present. That mask limits named user and group entries. Default ACLs affect new objects. Check effective access on the supported filesystems and test inheritance. Preserve the existing macOS check for an inheritable ACL on the registry directory. [Linux ACL rules](https://man7.org/linux/man-pages/man5/acl.5.html) · [macOS inheritance test](https://github.com/jccrosby/margin/blob/882b275ad93ecde9ee2c1fa93d3ac322c533b8d2/test/margin.test.js#L1318-L1339)
- Windows lacks `process.getuid()`. Node's mode bits cannot establish per-account privacy there. Windows uses file security descriptors and inherited access control lists. A restrictive directory alone does not prove that restored child files have restrictive permissions. Verify ownership and effective access for new and restored data. [Node process identity](https://nodejs.org/api/process.html#processgetuid) · [Node file modes](https://nodejs.org/download/release/v26.3.1/docs/api/fs.html#file-modes) · [Windows file access](https://learn.microsoft.com/en-us/windows/win32/fileio/file-security-and-access-rights)
- Margin commits each note with a same-directory hard link and flushes the directory. NTFS supports same-volume hard links. The existing read-only directory handle and flush sequence needs native Windows verification. Preserve complete-file publication, retry behavior, and recovery after interruption. [Note commit](https://github.com/jccrosby/margin/blob/882b275ad93ecde9ee2c1fa93d3ac322c533b8d2/src/notes.ts#L91-L135) · [NTFS links](https://learn.microsoft.com/en-us/windows/win32/fileio/hard-links-and-junctions) · [Windows flush requirements](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-flushfilebuffers)
- Margin requires SQLite write-ahead logging. SQLite documents that WAL does not work over a network filesystem. Decide source-root support separately from state storage support. Test privacy while `-wal` and `-shm` exist, and test a rebuild after notes are restored. [Margin index opening](https://github.com/jccrosby/margin/blob/882b275ad93ecde9ee2c1fa93d3ac322c533b8d2/src/index.ts#L95-L135) · [SQLite WAL](https://www.sqlite.org/wal.html)

## Native verification

Use synthetic projects and two unprivileged accounts on each supported filesystem. Check that the second account cannot read the registry, notes, evidence snapshots, or an active index and its sidecars. Cover inherited access and restores, including failure with an unsafe location. Verify that an unavailable notes directory leaves ordinary sources usable.

Exercise case aliases, Unicode names, and native paths with spaces. Verify that link and junction checks still hold when a source path changes between validation and read. On Windows, include a drive path and any network or namespace forms the support decision allows. Run concurrent saves, interruption, retry, export, restore, and index rebuild on native hosts. Include the note commit and registry replacement paths.

The repository's existing fixtures cover case aliases, Unicode differences, permissions, and interrupted writes. The platform findings above come from documentation and source. Native Windows and Linux runs remain open. [Margin fixtures](https://github.com/jccrosby/margin/blob/882b275ad93ecde9ee2c1fa93d3ac322c533b8d2/test/margin.test.js)
