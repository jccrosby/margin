# Native dependency support for Margin

Node, Git, Codex, Docling, and FFmpeg have native distributions for macOS, Windows, and Linux. The first release still needs a verified dependency set for each supported OS and architecture.

## Runtime and package

- Margin requires Node 26 and allows installs only on macOS today. The archive ships compiled JavaScript and exposes the `margin` command. Docling, FFmpeg, and Git are separate installs. [Margin package manifest](https://github.com/jccrosby/margin/blob/882b275ad93ecde9ee2c1fa93d3ac322c533b8d2/package.json#L2-L27) · [Evidence setup](https://github.com/jccrosby/margin/blob/882b275ad93ecde9ee2c1fa93d3ac322c533b8d2/docs/usage.md#search-documents-media-and-links)
- Node 26 ships macOS, Windows, and GNU/Linux binaries for x64 and ARM64. Node sets a macOS floor of 13.5 and requires `libatomic` for official Linux binaries. Its support table distinguishes glibc and musl. Those are Node requirements. The rest of the dependency set may set a higher floor. [Node platform and binary matrix](https://github.com/nodejs/node/blob/v26.x/BUILDING.md#platform-list)
- Node's bundled SQLite enables FTS5. The local macOS ARM64 check used Node 26.13.0 and found one match in an in-memory FTS5 table. Test FTS5 in the exact Node distribution selected for each OS. Margin also sets WAL mode, which needs separate on-disk and concurrent access checks. [Node SQLite build](https://raw.githubusercontent.com/nodejs/node/v26.x/deps/sqlite/sqlite.gyp) · [SQLite WAL](https://www.sqlite.org/wal.html) · [Margin index](https://github.com/jccrosby/margin/blob/882b275ad93ecde9ee2c1fa93d3ac322c533b8d2/src/index.ts#L80-L123)
- GitHub Packages requires a classic token with `read:packages` and package read access for a reader install. The scope and credential can live in npm's user config. Margin's instructions show a macOS path and POSIX permission commands. Windows setup needs a way to keep the reader token private outside the project and Codex config. [GitHub Packages npm registry](https://docs.github.com/en/packages/working-with-a-github-packages-registry/working-with-the-npm-registry#authenticating-to-github-packages) · [npm user config](https://docs.npmjs.com/cli/v11/configuring-npm/npmrc/#per-user-config-file) · [Margin setup](https://github.com/jccrosby/margin/blob/882b275ad93ecde9ee2c1fa93d3ac322c533b8d2/README.md#get-access-to-margin)

## Command launch and evidence

- Git for Windows provides native x64 and ARM64 builds. Margin invokes `git` directly and forwards a short environment list. Test Git lookup and project scans from the actual Codex process. A terminal may expose a different PATH. [Git for Windows releases](https://github.com/git-for-windows/git/releases) · [Margin Git call](https://github.com/jccrosby/margin/blob/882b275ad93ecde9ee2c1fa93d3ac322c533b8d2/src/git.ts#L3-L14)
- Codex publishes native CLI binaries for all three OSes and documents local stdio launch with separate command and arguments. npm creates Windows `.cmd` shims for package bins. Node's direct `execFile` does not launch a batch shim. Margin's package check uses that direct launch for an extensionless installed bin and for `pnpm`. Verify the configured Codex launch on a Windows host. A passing terminal command cannot establish that the MCP client can start it. [Codex release assets](https://github.com/openai/codex/releases/tag/rust-v0.171.0) · [Codex stdio setup](https://learn.chatgpt.com/docs/extend/mcp?surface=cli#stdio-servers) · [npm bin shims](https://docs.npmjs.com/cli/v11/configuring-npm/package-json/#bin) · [Node command launch](https://nodejs.org/api/child_process.html#spawning-bat-and-cmd-files-on-windows) · [Margin package check](https://github.com/jccrosby/margin/blob/882b275ad93ecde9ee2c1fa93d3ac322c533b8d2/scripts/check-package.js#L21-L38)
- Docling documents Windows, macOS, and Linux support. Its Intel Mac instructions require a compatible PyTorch release and Python 3.12 or lower. Margin launches `docling` directly, requests JSON, and disables OCR for inputs other than images. Validate the exact Docling release, its flags, and its OCR output with real files. [Docling installation](https://docling-project.github.io/docling/getting_started/installation/) · [Docling CLI](https://docling-project.github.io/docling/reference/cli/) · [Margin Docling call](https://github.com/jccrosby/margin/blob/882b275ad93ecde9ee2c1fa93d3ac322c533b8d2/src/evidence.ts#L95-L104)
- FFmpeg links to binaries for each OS. Margin uses `ffprobe` to detect subtitle streams and `ffmpeg` to emit WebVTT and PNG. A version check cannot prove those operations work with a chosen build. Check cue parsing and frame timestamps using that build's actual output. [FFmpeg downloads](https://www.ffmpeg.org/download.html) · [Margin media calls](https://github.com/jccrosby/margin/blob/882b275ad93ecde9ee2c1fa93d3ac322c533b8d2/src/evidence.ts#L150-L167) · [Frame extraction](https://github.com/jccrosby/margin/blob/882b275ad93ecde9ee2c1fa93d3ac322c533b8d2/src/evidence.ts#L205-L221)

## Native checks for the release decision

1. Run type checks and the full test suite on each supported configuration. Verify ranked search through FTS5 and concurrent SQLite access on local disk.
2. Install the same candidate archive on each OS. Run the documented CLI command and test a ranked search in a fresh Codex session. Use paths with spaces and non-ASCII text. Verify argument handling and clean stdio framing.
3. With a reader account and a cold cache, verify that the published version installs from GitHub Packages. Check that a fresh Codex session finds npm's user config. Keep the token out of command arguments and output.
4. Run extraction with genuine PDF, DOCX, and image fixtures. Test a subtitled video and a frame request. Check timestamps, content, and the gaps Margin reports when a tool is absent.
5. Exercise the support path from native Windows PowerShell. Margin's current source build uses `rm -rf`, its release scripts use Bash, and its only publish job runs on macOS. Decide which developer commands must run on Windows. The same archive can be tested on all three systems before a single publish job runs. [Margin package scripts](https://github.com/jccrosby/margin/blob/882b275ad93ecde9ee2c1fa93d3ac322c533b8d2/package.json#L13-L20) · [Release job](https://github.com/jccrosby/margin/blob/882b275ad93ecde9ee2c1fa93d3ac322c533b8d2/.github/workflows/release.yml)

This review verified local FTS5 on Apple silicon. Windows and Linux launches, authenticated installs, and real extractor runs remain open.
